영업·운영팀의 반복 업무와 분산된 데이터를 제품 안의 운영 흐름으로 전환했습니다. 요구사항을 UI·UX, 데이터 모델, API, 관리자·고객 화면으로 구체화하고, 고객사 평가 응답 시간 40초 → 10초, 건당 비용 90% 이상 절감, 실제 운영 기간 중 AI 상담 문의의 62%를 상담원 전환 없이 종결하는 성과를 만들었습니다.

CORE CAPABILITIES

  • 문제 정의·제품 전 과정 구현: 협업 피드백과 운영 흐름에서 문제를 찾고 UI·UX, 데이터 모델, API, 관리자·고객 화면으로 구체화
  • 운영 업무 구조화: 견적 이력·엑셀 일괄 수정, 입금·세금계산서·협력사 정산을 하나의 업무 흐름으로 통합
  • AI 제품화: 검색·추출·평가 파이프라인과 RAG 상담을 영업·마케팅·상담팀이 활용·운영하는 도구로 전환
  • 신뢰성 설계: fail-closed 검증, 결정론적 스코어링, 신뢰도 플래그와 관리자 검수 등 자동화와 사람의 판단 경계 설계
  • 성과 개선: 평가 시간 40초 → 10초, 평가 건당 비용 90% 이상 절감, 실제 운영 기간 중 AI 상담 문의의 상담원 무전환 종결률 62%, 웹 로딩 3초 → 0.7초

1. 견적 검토·일괄 수정·자동 산정 운영 효율화

2025.06 – 2026.07

기여 범위

기존 기획안을 바탕으로 견적 검토·승인/진행 불가의 기술 설계와 서버·관리자·고객 화면 구현을 담당하고, 중간 피드백을 반영했습니다. 견적 버전 관리·자동 산정은 설계부터 구현까지, 엑셀 일괄 수정은 기획 보강과 설계·구현을 전담했습니다.

배경

영업팀은 여러 부품의 옵션과 순서를 화면에서 반복해서 수정해야 했고, 복사된 견적은 원본과의 관계가 없어 어떤 견적에서 파생됐는지 일일이 검색해야 했습니다. 견적 변경 시 고객이 실제로 확인한 내용과 현재 데이터가 달라지면 영업–고객 간 의사소통의 기준도 모호해질 수 있었습니다.

주요 설계·구현

  • 기존 견적을 갱신하지 않고 원본 견적과 버전 번호로 계보를 구성하고, 새 버전 생성 시 견적 품목·조건·자유 견적 데이터도 함께 복제
  • 견적 계보·버전·식별자를 포함한 복합 인덱스로 버전 목록 조회와 정렬을 최적화하고, 트랜잭션 잠금 기반 애플리케이션 채번으로 동시 버전 생성 제어
  • 견적 검토 결과를 승인·진행 불가로 구분하고 사유·첨부·결제 차단을 서버·관리자·고객 화면에 일관되게 반영
  • DB의 현재 견적 데이터를 반영한 엑셀 템플릿을 생성하고 공정·재료·후가공·수량·단가·정렬 순서를 일괄 수정하도록 구현
  • 브라우저에서 화면이 보유한 품목·옵션 데이터로 엑셀을 파싱·1차 검증한 뒤 정제된 품목 배열만 서버에 전달
  • 서버는 최신 기준정보로 식별자·옵션 조합·수량·금액·순서·변경 가능 여부를 포함한 전체 행을 재검증하고, 모든 오류를 행·옵션 단위로 수집해 반환
  • 검증 단계에서는 DB 쓰기를 수행하지 않고, 오류가 없을 때만 견적 단위 잠금과 단일 트랜잭션으로 전체 변경을 반영하는 all-or-nothing 정책 적용
  • 편집 중 자동 견적 예상 단가·수량·최대 생산 수량을 미리 보여주고, 일부 형상·배치 조건에서 견적이 누락되던 계산 로직 개선

의사결정

변경분만 기록하는 방식보다 특정 시점에 고객이 확인한 견적 전체를 정확히 재현하는 것이 중요해 스냅샷 보존을 선택했습니다. 정규화된 데이터 구조로 복제 부담을 제한하고, 계보·버전 기반 인덱스와 트랜잭션 채번으로 조회와 동시 생성을 제어했습니다. 부분 반영 시 견적 계산 결과와 품목 순서가 서로 맞지 않는 불완전한 상태로 남을 수 있어, 오류가 하나라도 있으면 DB 쓰기를 시작하지 않고 전체 요청을 거부하는 all-or-nothing 방식을 적용했습니다. 브라우저는 빠른 피드백과 불필요한 요청 감소를, 서버는 최신 데이터 기준의 최종 정합성을 담당하도록 검증 책임을 분리했습니다.

성과

  • 영업팀이 상세 → 뒤로가기 → 검색 → 상세를 반복하던 견적 추적을 한 화면의 버전 탐색으로 전환해 휴먼 에러 가능성 감소
  • 여러 품목을 한 번에 수정할 수 있게 하고, 실제 사용자 피드백을 반영해 식별 컬럼·단위·열 너비·정렬·이미지 표시 등 세부 사용성 개선
  • 부분 성공으로 견적 상태가 불완전해지는 것을 막고, 잘못된 행과 옵션을 한 번에 확인한 뒤 수정하도록 오류 처리 경험 개선
  • 견적 상태·할인·옵션·산정 결과를 관리자·고객 화면과 견적 문서에 동일한 기준으로 반영

주요 기술 및 설계 포인트 — 견적 API, 관계형 데이터 모델, 버전 계보 복합 인덱스, 트랜잭션 잠금, 클라이언트·서버 이중 검증, 엑셀 일괄 수정, 자동 견적 계산

2. 입금·세금계산서·협력사 정산 운영 기준 정리

2026.01 – 2026.05

기여 범위

기능 요구사항을 바탕으로 별도 디자인 시안 없이 입금 대조·세금계산서·협력사 정산의 UI·UX, 데이터 구조, 서버 API와 관리자 화면 설계·구현을 전담했습니다.

배경

주문은 내부 관리자 시스템, 입금과 세금계산서는 은행·외부 발행 플랫폼, 협력사 정산은 본사·지사별 엑셀에서 각각 관리되고 있었습니다. 주문과 회계 데이터의 연결을 사람이 기록하고 누락분을 다시 찾는 과정에서 업무 부담과 휴먼 에러 위험이 컸으며, 담당자 변경 시에도 동일한 업무를 이어갈 수 있는 구조가 필요했습니다.

주요 설계·구현

  • 미완납 여부·통화·주문 상태·결제 방식 등으로 입금 연결 후보를 제한하고, 회사명·주문자명·입금 잔여액과 주문 미수금 일치도를 조합한 가중치로 추천 순서 구성
  • 입금자와 주문 정보가 다른 예외를 위해 회사·사용자·주문 ID 검색을 지원하고, 점수가 높아도 자동 연결하지 않고 담당자가 주문과 배분액을 최종 확정
  • 한 입금을 여러 주문에 배분할 수 있도록 관계를 분리하고, 입금 원장 행을 잠근 트랜잭션에서 누적 배분액이 입금액을 넘지 않도록 검증
  • UI에는 입금 잔여액과 주문 미수금 중 작은 값을 기본 배분액으로 제안하고, 연동 후 결제 로그를 기준으로 주문의 결제 완료 금액 재계산
  • 세금계산서 발행·취소·국세청 전송 상태를 내부 DB에서 관리하고, 여러 주문과 한 계산서의 관계를 명시적으로 연결
  • 발행 실패를 즉시 안내하고, 자체 시스템 장애 시 외부 플랫폼에서 발행한 계산서를 공식 승인 식별자로 사후 연결하거나 관리자에서 연동 해제할 수 있는 복구 경로 제공
  • 발주자–생산자 관계의 주문 트리에서 배송 완료 건과 생산자별 정산 후보 금액을 집계하고, 정산 담당자가 월별 완료 처리하도록 구현
  • 즉시 확정 결제 전 배송 예정일 변경 여부를 확인하고, 변경된 경우에만 고객 재승인을 받도록 연결

의사결정

입금 후보는 확정 조건으로 먼저 제한한 뒤 이름과 잔여 금액의 일치도를 조합해 설명 가능한 추천 순서를 제공했습니다. 입금자·주문자 불일치, 동일 금액 주문, 분할·합산 입금이 존재해 자동 연결 대신 담당자 확인을 유지했습니다. 배분은 입금 원장 잠금과 누적 금액 검증으로 정합성을 보장했으며, 세금계산서 오연결과 외부 발행에는 연동 해제·사후 연결 경로를 마련했습니다. 정산도 재배송과 조직별 입금 주기를 고려해 후보 집계와 담당자 확정을 분리했습니다.

성과

  • 은행 로그인·입금 확인·주문 반영으로 분리됐던 절차를 관리자 한 화면으로 통합하고, 담당자 교체 이후에도 동일한 처리 흐름 유지
  • 주문–세금계산서 관계와 발행 상태를 플랫폼에서 바로 확인해 엑셀 기반 매핑·누락 확인과 세무자료 정리 과정을 단일 흐름으로 전환
  • 본사·지사별 엑셀에 분산됐던 협력사 정산 대상·금액·월별 처리 이력을 플랫폼으로 통합
  • 시스템은 후보·기본 배분액·복구 수단을 제공하고 금전 데이터의 최종 판단은 담당자가 수행하도록 해 자동화와 회계 안정성의 균형 확보

주요 기술 및 설계 포인트 — 입금 후보 필터·가중치 정렬, 입금 원장 잠금, 배분 관계 모델, 전자세금계산서 연동, 주문–세무 관계 모델, 주문 트리 기반 정산 집계

3. RAG 기반 상담 자동화 및 답변 품질 운영 체계 구축

2025.08 – 2026.05

기여 범위

초기 기획과 검색·답변 구조 설계, 최초 구현을 담당했습니다. 이후 운영 단계의 주요 구조 개선과 고도화는 선임 개발자와 협업했습니다.

배경

같은 의미의 질문도 고객마다 표현이 달라 키워드 매칭만으로 적절한 FAQ를 찾기 어려웠습니다. 실제 고객 대상 운영에서는 제조업 일반 지식을 근거로 회사가 제공하지 않는 공정까지 지원 가능하다고 안내하는 사례도 발견했습니다. 이를 단순 프롬프트 문제가 아니라 공정·재료·마감 지식이 같은 검색 범위에 섞여 질문 의도와 다른 근거가 선택되는 문제로 정의했습니다. 또한 견적 가격이나 배송 사후 처리처럼 거래 정보 확인과 운영 판단이 필요한 문의는 AI가 임의로 처리해서는 안 됐고, 비개발 운영자가 지식과 답변 품질을 직접 관리할 수 있어야 했습니다.

주요 설계·구현

  • FAQ의 질문–답변 쌍을 하나의 검색 단위로 구성하고, 고객 질문과 의미적으로 가까운 FAQ를 찾는 벡터 검색 기반 마련
  • 실제 상담 질문을 공정·재료·마감 카테고리로 라벨링하고, LLM이 질문 의도를 먼저 분류한 뒤 해당 영역의 지식만 검색하도록 도메인별 검색 라우팅 적용
  • 일반 제조 지식보다 자사 서비스 정보를 우선 근거로 사용하도록 검색 컨텍스트를 제한해 미지원 공정 안내 위험 축소
  • 사용자 질문과 AI 답변을 기록해 관리자 화면에서 검토하도록 하고, 지식베이스를 바로 추가·수정할 수 있는 UI·UX 설계
  • 변경한 지식을 실제 대화 형태로 즉시 검증하는 채팅 테스트 허브를 구축해 개발·배포 없이 답변을 갱신하고 오류를 확인하도록 지원

의사결정 보강

단일 벡터 검색의 유사도만으로는 의미가 비슷한 제조 지식과 실제 제공 가능한 서비스 정보를 구분하기 어렵다고 판단했습니다. 프롬프트에 지원 범위를 나열하는 방식보다 상담 데이터의 도메인 라벨과 LLM 의도 분류를 이용해 검색 단계에서부터 컨텍스트 범위를 제한했습니다. 자동 응답 여부는 단일 임계값에 맡기지 않고 검색 결과, 답변 가능 여부와 고객의 상담 요청을 함께 고려해 상담원 전환 경로를 유지했습니다.

의사결정

표현이 다른 동의 질문을 처리하기 위해 키워드 일치 대신 의미 유사도 검색을 적용했습니다. 전환 여부는 단일 기준에 맡기지 않고 키워드·카테고리 규칙, 검색 유사도, LLM의 답변 가능 여부 분류와 사용자 직접 요청을 함께 사용했습니다. 적절한 FAQ를 찾지 못하거나 견적 가격·배송 사후 처리처럼 운영 판단이 필요한 문의는 상담원에게 연결했습니다.

성과

  • 상담원 전환 없이 종결된 AI 상담 비율 62%

4. LLM 기반 고객사 평가 제품화

2025.10 – 2026.04

기여 범위

기획에 참여하고 고객사 평가의 UI·UX, 서버 아키텍처와 구현을 전담했습니다.

배경

기존에는 고객사를 산업군으로 분류하고 필요할 때 누적 주문액을 엑셀로 추출해 영업에 참고하는 수준이었습니다. 기업 메타정보와 재무정보를 결합한 평가가 필요했지만, 초기 단일 LLM 구조는 탐색 범위가 넓어 필요한 정보의 검색 성공률이 낮고 추론 강도를 높여도 품질 개선에 한계가 있었습니다. 처리 시간도 길어 고객 정보 입력 완료 시점에 평가 데이터가 준비되지 않는 문제가 있었습니다.

주요 설계·구현

  • 알파 테스트 결과를 바탕으로 하나의 LLM이 검색·추출·평가를 모두 처리하던 구조를 기업 메타정보 수집과 재무정보 수집의 병렬 파이프라인으로 전환
  • 10억, 1000000000 처럼 표현과 단위가 다른 재무 수치를 LLM이 사전 규칙에 따라 표준화하고, 정제된 값은 기존 평가 기준이 반영된 결정론적 함수로 스코어링
  • 재무정보 신뢰성 키워드 맵과 기준치를 두고 미달 데이터에는 신뢰성 의심 플래그를 부여해, 관리자가 원문 출처 링크를 확인한 뒤 평가 제외 또는 신뢰 정보로 판정하도록 구현
  • 회원가입 완료 전에 평가가 끝나도록 처리 시간을 줄여 평가 정보를 포함한 외부 분석 이벤트가 누락되지 않도록 개선

의사결정

알파 테스트에서 단일 LLM 구조의 낮은 정보 검색 성공률, 긴 처리 시간과 높은 추론 비용을 확인해 기업 메타정보와 재무정보 수집을 병렬 파이프라인으로 분리했습니다. 검색 그라운딩으로 확보하기 쉬운 메타정보에는 낮은 추론 강도, 비정형 재무정보의 해석·정규화에는 높은 추론 강도를 적용해 동일 모델의 자원을 작업 난이도별로 배분했습니다. 정규표현식만으로 다양한 수치 표현을 처리하기 어려워 LLM이 의미 해석과 표준화를 담당하고, 평가는 기존 기준을 일반 코드로 계산하도록 책임을 분리했습니다. 비용과 필요한 데이터 범위를 비교해 재무정보 전문 API 대신 웹 검색 API를 선택했습니다. 결과적으로 LLM은 비정형 정보의 의미 해석에 집중하고 평가 기준과 점수 계산은 일반 코드로 분리함으로써 설명 가능성과 재현성을 동시에 확보했습니다.

성과

  • 기업 메타·재무정보 수집 병렬화로 평가 응답 시간 40초 → 10초 단축해 고객 정보 입력 완료 시점에 평가 데이터가 준비되도록 하고, 평가 정보가 포함된 외부 분석 이벤트 누락 방지
  • 웹 검색 API와 작업별 추론 강도 최적화로 평가 건당 비용 90% 이상 절감
  • LLM의 유연한 비정형 정보 해석과 일반 코드의 재현 가능한 점수 계산을 분리해 평가 설명 가능성과 일관성 확보
  • 자동 분류된 고객군을 타깃 메일링·프로모션과 유입 고객 통계 기반 캠페인 기획에 활용할 수 있는 데이터 기반 마련

주요 기술 및 설계 포인트 — LLM API, 웹 검색 API, 병렬 정보 수집, 비정형 데이터 정규화, 결정론적 스코어링, 관리자 신뢰도 검수 화면

2025.03 – 2026.04

기여 범위

배경

관리자 편집 미리보기와 공개 웹·가이드·블로그는 앱별 파서·스타일·래퍼가 달라 같은 문서가 서로 다르게 표시됐고, SEO·다국어 처리도 표면마다 흔들렸습니다. CDN에서는 대용량 원본 PNG가 그대로 제공돼 페이지 로드가 느렸습니다. ISO/IEC 27001 인증 심사 대응을 위해 공급 파트너에게 스토리지 URL을 직접 노출하지 않고 현재 거래 관계에 따라 도면 접근을 통제할 필요가 있었습니다.

  • 별도 CMS를 늘리지 않고 공용 콘텐츠 모델을 유지한 채 경로·표시 형태·언어 설정으로 각 화면을 구분하고, 수정 이력·다국어 revision·SEO 메타데이터·사이트맵·구조화 데이터 계약 통합
  • 구성원 피드백과 브라우저 네트워크 패널로 원본 PNG 전송 병목을 진단하고, 코드·DB·콘텐츠의 이미지 참조 위치를 매핑한 뒤 원본 해상도를 유지한 WebP로 일괄 이전
  • 최적화 이미지를 올바른 콘텐츠 유형의 새 객체로 업로드하고 참조 URL을 갱신한 뒤 CDN 캐시를 무효화했으며, 원본은 별도 백업

  • 스토리지 직접 노출을 제거하고, 협력사 세션·초대 관계·현재 거래 상태를 매 요청 검증하는 보호 API 구축

  • 언어·구독 유형·오프라인 고객 그룹별 마케팅 메일 발송, 구독 해지와 발송 이력 관리 구현
