1. 분석 서비스 AWS 재해복구·자동 전환

2026.07 – 2026.08

건물 정전·온프레미스 네트워크 장애는 현장 조치가 필요해, 주말에는 복구에 이틀 이상 걸리는 경우도 있었습니다. 예정·돌발 장애 모두 재개 시점을 예측하기 어려워, 서버 복구와 분석 업무 재개를 분리하는 AWS 자동 전환을 설계·구현해 운영 환경에 적용했습니다.

  • 예정 정전은 관리자 예약 기동, 돌발 장애는 30초 주기 상태 신호·CloudWatch Alarm으로 대응했습니다. Lambda에서 장애·예약 수요를 함께 확인해 어느 한쪽이라도 남으면 클라우드 분석을 유지했습니다.
  • ECS Fargate를 평상시 0개, 장애 시 최소 1개에서 최대 2개로 기동해 기존 BullMQ 대기열을 처리하도록 연결했습니다. 온프레미스 복구 전에도 클라우드가 분석을 이어받도록 했습니다.
  • 진행 중인 작업은 자원 자동 축소로 중단되지 않도록 보호했습니다. 장애·예약 수요가 모두 끝나면 남은 작업을 마친 뒤 분석 자원을 자동 종료해 유휴 비용을 제한했습니다.
  • DR 분석서버 평균 기동시간 약 5분, 평상시 상태 감시 고정비 월 약 2달러로 운영했습니다. 장애·예약 시 분석 실행비는 별도이며, 상시 예비 분석 서버를 두지 않는 비용·기동시간 절충을 택했습니다.

2. LLM 기반 고객사 평가

2025.10 – 2026.04

기획에 참여하고 UI·UX, 서버 아키텍처와 구현을 전담했습니다. 단일 LLM이 검색·추출·평가를 모두 맡아 느리고 비용이 높았으며, 매번 달라질 수 있는 결과를 영업 업무에 쓰기 위한 검증이 필요했습니다.

  • 기업 메타정보와 재무정보 수집을 병렬 파이프라인으로 나누고, 작업 난이도에 따라 추론 강도를 달리 적용했습니다.
  • LLM은 비정형 재무 수치를 해석·표준화하고, 점수는 코드가 기존 기준대로 계산해 같은 입력에 같은 결과가 나오도록 했습니다.
  • 신뢰성 키워드와 기준치로 의심 데이터를 표시하고, 관리자가 원문 출처를 확인해 평가 제외 여부를 판단하도록 했습니다.
  • 병렬 수집으로 평가 응답 시간 40초 → 10초를 달성해 고객 정보 입력 완료 시점에 결과가 준비되도록 했고, 웹 검색 API·추론 강도 최적화로 건당 비용을 90% 이상 절감했습니다.

3. 입금·정산 통합과 결제 안전성

2026.01 – 2026.09

은행·외부 발행 플랫폼·엑셀에 분산된 입금·세무·정산을 관리자 한 흐름으로 통합하며 UI·UX, 데이터 구조, API와 화면 설계·구현을 전담했습니다. 후속으로 결제 재시도·지연 승인에 대응하는 복구 경로를 구현했습니다.

  • 분할·합산 입금과 주문자 불일치 때문에 자동 연결 대신 후보 추천·담당자 확정을 택하고, 원장 잠금·누적 배분 검증으로 초과 연결을 막았습니다.
  • 세금계산서 사후 연결·오연결 해제와 주문 트리 기반 월별 협력사 정산을 구현했습니다. 지사→외부 생산자 정산은 출고일 대신 지사 입고 완료일을 기준으로 삼았습니다.
  • 결제 재시도에서 외부 조회는 데이터 잠금 밖에서 수행했습니다. 다시 잠근 뒤 현재 결제 시도가 바뀌지 않았을 때만 갱신해 이전 요청이 최신 상태를 덮어쓰지 않도록 했습니다. 금액 변경 시 이전 주문을 보존하고 새 주문을 생성했습니다.
  • 결제 시도·금액·통화를 검증해 최초 유효 승인과 중복을 구분했습니다. 중복 승인 취소 요청을 저장해 실패 시 재시도하고, 취소 전 정상 승인 건을 재확인해 잘못된 취소를 막았습니다.

4. 견적 버전 관리·일괄 수정

2025.06 – 2026.09

고객이 확인한 견적을 재현하고 대량 수정이 일부만 반영되지 않도록 하는 것이 핵심이었습니다. 검토·승인은 기존 기획의 기술 설계·전 화면 구현, 버전 관리는 설계·구현, 견적 일괄 수정은 기획 보강·설계·구현을 담당했습니다.

  • 변경분만 기록하지 않고 원본–버전 계보와 견적 전체 스냅샷을 보존했으며, 복합 인덱스와 트랜잭션 잠금 기반 채번으로 동시 생성을 제어했습니다.
  • 견적 일괄 수정은 브라우저에서 빠르게 1차 검증하고 서버가 최신 기준정보로 전체 행을 재검증한 뒤, 오류가 없을 때만 한 트랜잭션으로 모두 반영했습니다.
  • 견적 추적을 한 화면의 버전 탐색으로 전환하고, 부분 성공으로 금액·품목 순서가 불완전해지는 상태를 방지했습니다.
