1. 분석 서비스 AWS 재해복구·자동 전환

2026.07 – 2026.08

정전·네트워크 장애로 현장 복구에 이틀 이상 걸리기도 했던 분석 서비스에 AWS 자동 전환을 설계·구현하고 운영 환경에 적용했습니다.

  • 평상시에는 온프레미스에서 분석하고, 장애·예약 시 Fargate가 기존 BullMQ 대기열을 이어 처리하도록 구현했습니다. 상시 예비 서버 비용을 피하는 대신 DR 분석서버 평균 기동시간 약 5분을 수용했습니다.
  • 예정 정전은 관리자 예약, 돌발 장애는 30초 주기 상태 신호·CloudWatch Alarm으로 감지했습니다. Lambda가 두 수요를 함께 확인하고, 진행 중인 작업을 보호한 뒤 수요가 모두 끝나면 남은 작업을 마치고 자원을 종료하도록 했습니다.
  • Fargate는 평상시 0개·장애 시 1~2개로 운영하며, 상태 감시 고정비는 월 약 2달러입니다. 장애·예약 시 분석 실행비는 별도입니다.

2. LLM 기반 고객사 평가

2025.10 – 2026.04

단일 LLM이 검색·추출·평가를 모두 처리하던 고객사 평가의 기획에 참여하고, UI·UX·서버 아키텍처 설계와 구현을 전담했습니다.

  • 기업 메타·재무정보를 병렬 수집해 평가 시간 40초 → 10초로 줄여 고객 정보 입력 완료 시점에 결과가 준비되도록 했습니다. 웹 검색 API·작업별 추론 강도 최적화로 건당 비용을 90% 이상 절감했습니다.
  • 재무 수치의 해석·표준화는 LLM에 맡기고, 평가 점수는 코드로 계산해 같은 정제 입력에 같은 점수가 나오도록 했습니다.
  • 데이터 부재와 AI 장애를 구분하고 신뢰성 키워드·기준치로 의심 데이터를 표시했습니다. 관리자가 원문을 확인해 평가 제외 여부를 결정하도록 구현했습니다.

3. 입금·정산 통합과 결제 안전성

2026.01 – 2026.09

은행·외부 발행 플랫폼·엑셀에 분산된 입금·세무·정산을 통합하며 UI·UX, 데이터 구조, API·관리자 화면을 전담하고 후속 결제 복구 경로를 구현했습니다.

  • 입금 연결은 분할·합산 입금과 주문자 불일치를 고려해 후보 추천·담당자 확정으로 구현했습니다. 한 입금을 여러 주문에 배분하되 원장 잠금·누적 배분 검증으로 초과 연결을 막았습니다.
  • 세금계산서는 외부 발행 건의 사후 연결과 오연결 해제를 지원하고, 협력사 정산은 주문 트리 기준으로 월별 대상을 집계했습니다.
  • 결제 재시도는 외부 상태 조회를 DB 잠금 밖에서 수행하고, 다시 잠근 뒤 현재 결제 시도가 같을 때만 갱신해 이전 요청의 상태 덮어쓰기를 막았습니다.
  • 중복 승인은 결제 시도·금액·통화로 구분했습니다. 취소 요청을 저장해 실패 시 재시도하고, 취소 전 정상 승인을 재확인하도록 했습니다.

4. 견적 버전 관리·일괄 수정

2025.06 – 2026.09

견적 검토·승인은 기존 기획의 기술 설계·전 화면 구현을, 버전 관리는 설계·구현을, 일괄 수정은 기획 보강·설계·구현을 담당했습니다.

  • 견적 버전 관리는 원본과 각 버전의 관계·전체 스냅샷을 저장해 고객이 확인한 견적을 재현하고 한 화면에서 버전을 탐색하도록 구현했습니다. 조회에는 복합 인덱스, 동시 생성에는 트랜잭션 잠금 기반 채번을 적용했습니다.
  • 견적 일괄 수정은 브라우저 오류 안내와 서버의 최신 기준정보 검증을 거쳐, 전체 행에 오류가 없을 때만 단일 트랜잭션으로 반영해 부분 수정을 막았습니다.
