# Pending 문서 규칙

`pending/`에 문서를 저장·수정할 때와 `pending/` 내용을 SoT에 반영할 때 적용한다. `pending/`은 이력서·경력기술서의 미반영 사항을 정리하는 로컬 작업 디렉터리이며, `.gitignore`로 git 추적에서 제외된다.

## 경로

```text
pending/${yyyy-MM}/${dd}/${aspect}.md
```

| 요소 | 값 |
| --- | --- |
| `${yyyy-MM}` | 문서를 작성한 연-월 (`2026-02`) |
| `${dd}` | 문서를 작성한 일, 2자리 (`09`, `13`) |
| `${aspect}` | 다루는 측면을 나타내는 영문 소문자 kebab-case 슬러그 (`military`, `education`, `side-project`) |

예: `pending/2026-02/13/military.md`

## 메타데이터

모든 문서는 파일 최상단에 메타데이터 블록을 두고, `---`로 본문과 구분한다.

```markdown
- 최초 작성일: 2026-09-13
- 상태: 검토 대기 — 이력서·경력기술서 SoT 미반영
- 대상 문서: `content/resume-sot.md`, `content/work-experience-sot.md`
- 목적: 기존 경력의 강점과 신규 개발이력, 코드·커밋 검증 결과를 결합해 두 문서의 최종 구성·반영 문구·근거·보류 조건을 제안한다.

---

# 문서 제목
```

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| 최초 작성일 | 필수 | `yyyy-MM-dd`. 경로의 `${yyyy-MM}/${dd}`와 반드시 일치해야 한다 |
| 상태 | 필수 | 아래 상태 값 중 하나. `— 부연`을 덧붙일 수 있다 |
| 대상 문서 | 필수 | 반영 대상이 될 SoT 파일의 저장소 루트 기준 경로를 백틱으로 나열. 아직 정하지 않았으면 `미정` |
| 목적 | 필수 | 문서가 무엇을 정리·제안하는지 한 문장 |

조사 출처를 식별할 수 있는 정보(저장소 경로·이름, 커밋 해시, 내부 시스템명 등)는 메타데이터에 기록하지 않는다. 검증 사실을 남길 필요가 있으면 `목적`에 추상적으로만 적는다.

### 상태 값

| 상태 | 의미 |
| --- | --- |
| `검토 대기` | 기본 상태. SoT 미반영 |
| `보류` | 반영을 미룸. `— 사유`를 붙인다 |
| `반영 완료` | SoT에 반영됨. `— yyyy-MM-dd, 반영된 문서`를 붙인다 |
| `폐기` | 반영하지 않기로 확정. `— 사유`를 붙인다 |

문서를 갱신할 때 `최초 작성일`은 바꾸지 않고, `상태`·`대상 문서` 등 나머지 필드는 현재 상태로 갱신한다.

## 규칙

- 경로 날짜는 최초 작성 시점으로 고정한다. 이후 수정은 파일을 새로 만들지 않고 같은 경로의 파일을 갱신한다.
- 같은 날 같은 `aspect`는 하나의 파일로 유지한다.
- `pending/`은 SoT가 아니다. 사용자가 명시적으로 반영을 지시하거나 파일을 지목한 경우에만 `content/resume-sot.md` 또는 `content/work-experience-sot.md`에 반영한다.
- `pending/` 아래 파일은 커밋·stage하지 않는다.
